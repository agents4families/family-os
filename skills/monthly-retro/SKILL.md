# Monthly Retro

## Purpose
The family OS improves only if someone looks at it. This closes the loop: outcomes, fairness, and system changes. It's also the check that nobody is silently carrying the mental load.

## Autonomy
A1. Proposes changes to context, skills, and autonomy levels. Adults approve.

## Context to load
- `harness/state/progress.md` and `learning-log.md` (last 30 days)
- `harness/state/tasks.json` (done, dropped, overdue)
- `outputs/weekly/` for the month; `context/charter.md` (the mental-load split)
- `harness/autonomy-ladder.md`

## Steps
1. **Scorecard** (from files, not memory):
   - Weekly summits held: x of 4
   - Tasks completed on time / overdue / dropped
   - Surprises: things that went wrong because the system missed them (ask the adults)
   - Agent errors: wrong date, wrong owner, bad draft, unsafe suggestion
   - Mental-load balance: tasks by owner by domain versus the charter split
2. **What worked:** three bullets, with the skill or habit responsible.
3. **What didn't:** three bullets, with a root cause (missing context, bad skill, tool limit, human habit).
4. **Fairness check:** if one adult owns far more than the agreed split, say so neutrally and offer rebalancing options. Don't assign blame.
5. **Propose changes**, each as a diff: new or changed context facts, `AGENTS.md` rules (from corrections that repeated), skill edits, autonomy promotions or demotions, connectors to add or drop.
6. **Run `os-audit`** for staleness and context bloat.
7. **Pick one experiment** for next month (e.g., Sunday summit moved to Saturday morning).

## Output contract
`outputs/retros/YYYY-MM-retro.md`: scorecard table, worked/didn't, proposals as approvable diffs, one experiment.

## Guardrails
- Facts first, then interpretation. If data is thin, say so.
- Promotions only per the checklist in `autonomy-ladder.md`.
- Keep it honest and kind. This isn't a performance review of either adult.

## Done when
Approved changes are applied and logged, and the next month has one named experiment.
